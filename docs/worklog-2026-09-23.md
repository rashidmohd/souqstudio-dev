## 1. The admin panel — E13's foundation and three surfaces

`apps/admin` had an env module, a stylesheet, a health route and six empty directories.
`admin_users` and `admin_audit_logs` had existed since the baseline migration and nothing
had ever read either one.

### Built

| Piece | Where |
| --- | --- |
| Staff sessions | `admin_sessions` (new), `lib/admin-session.ts`, `auth/{login,logout}` |
| Role vocabulary | `lib/admin-roles.ts` — pure, client-safe |
| Authorization | `lib/admin-auth.ts` — `requireAdmin`, `requireAdminRole`, `requireAdminApi` |
| IP allowlist | `lib/ip-allowlist.ts` + `middleware.ts` |

| Block library console | `/blocks`, `/blocks/[id]`, `lib/library-client.ts` |
| Prompt management | `/prompts`, `/prompts/[id]`, `/prompts/new` |

### Three decisions worth not reversing

**A session table, not a signed stateless cookie.** The scaffold's
`ADMIN_SESSION_SECRET` implied stateless; the variable stayed and its job changed. A staff
session reaches every organization, so ending one has to be a fact about the system rather
than a wait for an expiry. The secret now keys the stored hash, which buys one operational
control: rotating it ends every staff session at once, with no migration and no deploy.
`isActive` is the other half — the admin row is re-read every request, so switching
somebody off is immediate.

**Publishing calls `apps/web`; it does not write R2.** `library-auth.ts` called
`LIBRARY_PUBLISH_TOKEN` "a placeholder for E13's admin auth". The panel replaces the
placeholder by becoming the token's *holder*, not by reimplementing what it guards — the
document schema, the manifest and the loader's refusal rules stay in one place. The token
stops being the credential and the staff session becomes it.

**The console describes blocks; it does not draw them.** A preview needs
`draw.tsx`, which carries ~30 imports from `apps/web`'s own lib and ui. Copying it is the
second painter CLAUDE.md warns about; extracting it is real work E9 wants anyway. So the
screen reports arrangements, aspect ranges and bindings, and shows the stored thumbnail.

### Corrections to E13's spec

- **E13 asks for shadcn/ui.** `components/ui/` is nine hand-built primitives instead:
  every shadcn component needs its shadows stripped and radius corrected first, and this
  app needs a fraction of the set.
- **E13 asks for TanStack Table and Tremor.** Both are dependencies and neither is used.
  Every list is filtered and paged on the server, because the universal catalog is already
  18,428 rows and a client table would need all of them to filter any of them.
- **E13-04 says "same as E7, accessed here".** It is not: E7's designer is where a block
  is drawn, this is where one is published.
- **The epic does not mention prompt management.** It is here because the gap was real —
  `cover_prompts` moved into the database in September *specifically* so the art direction
  could be tuned, and until now was editable only with SQL.

### Verified live

Signed in against the Railway database and exercised it: login refuses a wrong password
and an unknown address identically, an off-allowlist request gets a flat 404, `/api/health`
stays exempt, a slug change is refused, a too-short scene is refused, a no-op save writes
no audit row, and logout revokes the session. The migration was applied with approval and
the first super admin created from the shell.

**Not verified:** the role gate, live. Creating a second admin was denied by a permission
prompt, so it rests on `admin-roles.test.ts`.

## 2. E14 — Phase 2, Phase 4 and Phase 5

### Phase 2 — frames, the solver, placement

`frame.ts` (types, schema, validity rules), `solve.ts` (the two-pass solver), `place.ts`
(the scalar, per slot class, the legibility floor). Nothing renders, which is the exit
criterion rather than a shortfall.

**The frame tree is deliberately not in `BlockElement`.** 72 call sites switch on
`element.kind`; joining that union is Phase 5's or later's job. `LayoutLeaf.ref` carries
the element id so the join is a lookup rather than a rewrite. That decision paid for
itself twice — Phase 4 and Phase 5 were both finishable without touching a painter.

**Three things the design left open, settled here.** `stretch` does not override a cross
size set by hand (flexbox and Figma agree). `hug` is refused on a `free` frame, because
hugging fractions of yourself has no fixed point. `between` on a hugging axis is refused
rather than cut — §8 leaned cut; refusing keeps it for the wide band and avoids a silent
fallback to `start`.

### Phase 4 — the gate, passed

`pnpm --filter @souqstudio/engine frames` builds five blocks by hand and writes
`harness/out/frames.html`. **The model survives.** The row anchored at its end extends
left as the price grows; the star *is* the frame; the 3-up band with a spanning card works
and mirrors.

**Three defects, none of which a unit test caught, all found by looking at a picture:**

1. **Out-of-flow children were reordered**, so they painted underneath. The burst card's
   star solved before the packshot and was covered by it. The geometry was correct the
   whole time, which is exactly why nothing failed.
2. **A column never wrapped its text.** The re-measure fired only for rows. The rule that
   fixes it is worth stating: *the horizontal axis is resolved first, whichever axis that
   is*, because text height depends on text width and never the reverse.
3. **The harness measured one way and drew another.** Both now call one `wrapText`. A
   harness whose picture disagrees with its own geometry is worse than none, because the
   picture is what gets reviewed.

**Two findings for the model, not defects.** A hugging frame hugs its bounding box, not
the shape's usable interior — `MARK_FIT` already solves this for the price mark and a
frame with `shape` set should reuse that table. And `baselineAlign` is still only
recorded; it needs a font metric.

**The measurement §8 asked for:** a 3-up band with a spanning card costs exactly three
depth levels, which is the cap. A span is *a column that does not subdivide*. Nothing in
these five needs `grid` as a third layout mode; anything past them is one level short.

### Phase 5 — the converter, and a contradiction in its own exit

`pnpm --filter @souqstudio/engine convert:check`:

```
66 blocks, 1876 element rects compared in both editions
worst drift: 0.00e+0
geometry is identical through both paths
```

Exactly zero, and true by construction: an arrangement becomes a `free` frame holding one
leaf per element at the box it already had, and the solver runs the same arithmetic on it
that `resolveBlock` does.

**The survey found three things before any code was written.** `groupId` is used by
nothing — 938 elements, zero group runs — so the plan's "every `groupId` run becomes a
`free` frame" is a no-op. `logo` was already folded into `image` by Phase 1.3. And the
library is 66 blocks, not the 83 the plan says.

**Phase 5's two instructions cannot both hold.** It asks that every `priceMark` become a
frame, and that the render be byte-identical. `layoutPriceMark` positions its pieces from
*the amount being drawn*, so a mark's internal geometry is a function of the price: there
is no fixed set of boxes to bake in, and no differently-fitting frame lands on the same
numbers for every offer. Same for `chip`.

So the converter leaves both as leaves at their own boxes and records a note naming why.
104 price marks and 75 chips are counted, not silently moved, and they are Phase 6's
worklist — §4 already says what each becomes, and converting them mechanically would mean
authoring every price mark twice.

**One deviation:** `convert:check` diffs geometry, not rendered SVG. Byte-identical SVG is
a proxy for "the geometry did not change"; comparing floats tests the same claim without
coupling it to a renderer, which matters because a converted tree cannot reach
`harness/svg.ts` until the union is joined.
